## 1. システム名称の変更（最優先・先に片付ける）

Codexが自動生成した現在のシステム名を、**「スマートフォン検品システム」**に統一してください。

対象箇所の例（漏れがないか確認すること）:
- `package.json` の `name`
- `src/app/layout.tsx` などの `<title>` / metadata
- README.md のタイトル
- 画面ヘッダーやログイン画面などに表示されているサービス名
- メールテンプレートなど文言が出る箇所があれば全て

技術的な識別子（npmパッケージ名・フォルダ名など日本語にできない部分）は
`smartphone-inspection-system` のような英語スラッグのままで構いません。
**画面に表示される文言(表示名)はすべて「スマートフォン検品システム」に統一する**、という方針です。

他の変更より前に対応してください（影響範囲が広いため、後回しにすると差分が大きくなります）。

## 2. 端末情報の自動取得（USBケーブル接続）

### 背景・目的

現在、新規検品登録画面では端末情報（モデル名・ストレージ容量・IMEI・バッテリー状態・充電回数）を
すべて手入力している。これを、検品対象のスマホと本システムを動かしているPCをUSBケーブルで
接続するだけで自動取得できるようにしたい。

### 技術方針

ブラウザ単体ではUSB接続されたスマホの内部診断情報（IMEIやバッテリー状態など）に直接アクセス
できないため、PC側で動く**ローカルブリッジプログラム**を新設し、Next.jsアプリとローカル通信させる
構成にする。

```
[検品対象スマホ] --USBケーブル-- [検品PC]
                                    │
                      ┌─────────────┴─────────────┐
                      │ ローカルブリッジ (Node.js常駐プロセス)  │
                      │ ・Android: ADBコマンドを実行          │
                      │ ・iPhone : libimobiledeviceを実行     │
                      └─────────────┬─────────────┘
                                    │ localhost API (例: http://localhost:4123)
                                    ▼
                      [Next.jsアプリ (ブラウザ)]
```

- **Android**: `adb devices` で接続検知 → `adb shell getprop ro.product.model`（モデル名）、
  `adb shell dumpsys battery`（バッテリー状態）、ストレージ容量、IMEI（`adb shell service call
  iphonesubinfo 1` 等。取得できるかは端末・OSバージョンに依存）を取得する。
- **iPhone**: `libimobiledevice` の `ideviceinfo` コマンドを利用し、モデル名・ストレージ容量・
  シリアル番号・IMEI（取得できる場合）を取得する。初回接続時は端末側で「このコンピュータを
  信頼しますか」への許可操作が必要になる。
- ブリッジプログラムは別ディレクトリ（例: `bridge/`）に用意し、検品PC側に事前にADB／
  libimobiledeviceをインストールしておく前提とする。READMEにセットアップ手順を明記する。
- 新規APIエンドポイント `GET /api/device-detect` を追加し、ブリッジから受け取った最新の
  接続端末情報を新規検品登録画面に反映する。

### 必ず守ってほしい設計方針（重要）

- **自動取得できなかった項目は手入力にフォールバックする「ハイブリッド設計」にすること。**
  Androidのバージョンやメーカーによっては、プライバシー保護のためIMEIやバッテリー詳細情報を
  一般アプリから取得できない場合がある(ADB shell経由なら取得できることが多いが、100%保証はできない)。
  「取れたら自動入力、取れなければ手入力欄をそのまま使える」という前提で実装する。
- 端末が接続されていない場合は、これまで通りすべて手入力で登録できる状態を維持する
  （後方互換性を壊さない）。

### 受け入れ条件

- 対応済みAndroid端末をUSB接続した状態で新規検品登録画面を開くと、モデル名・ストレージ容量が
  自動入力される。
- IMEI・バッテリー情報が取得できた場合は自動入力欄に反映され、できない場合は空欄のまま
  手入力できる。
- 端末を接続していない状態でも、これまで通り全項目手入力で登録できる。

## 3. にこスマの価格情報取得バッチ

### 背景

班長から「にこスマのサイトから、機種ごと・状態(グレード)ごとの価格を取得するプログラムが欲しい」
という依頼があった。

### 技術方針

- にこスマの買取／販売価格ページを対象に、機種名・グレード(A/B/C等)・価格を取得し、
  DBに保存するバッチ処理を追加する。
- 新規テーブル `PriceReference`（機種名, グレード, 価格, 取得日時）を追加する。
- 取得処理は `src/server/priceScraper/` 配下に実装し、静的HTMLであれば `cheerio`、
  動的にレンダリングされるページであれば `playwright` を使用する。
- まずは手動実行できるCLIスクリプト(`npm run scrape:prices`)として実装する。余裕があれば
  GitHub ActionsやNext.jsのCron機能で定期実行（例: 1日1回）に発展させる。
- **サイトへの配慮を必ず組み込むこと**：
  - リクエスト間隔を空ける（1件ごとに数秒待つ）
  - robots.txtの内容を確認し、許可された範囲でのみ取得する
  - 短時間に大量アクセスしない
  - 取得したデータは自分たちのDBにキャッシュし、毎回サイトへアクセスしない設計にする
- 取得した価格データは、検品結果画面や(発展機能の)顧客向け事前スキャン画面で
  「参考買取価格」として表示できるようにする（表示自体は次フェーズでよく、まずはデータの
  取得・保存までを実装する）。

### 受け入れ条件

- `npm run scrape:prices` を実行すると、にこスマのページから機種・グレード・価格を取得し
  `PriceReference` テーブルに保存される。
- 同じ機種・グレードのデータを再取得した場合、まずは追記型（履歴として残す）でよい。

## Codexへの実装指示（まとめ）

1. まず「1. システム名称の変更」を対応する（影響範囲が広いため最初に片付ける）。
2. 「2. 端末情報の自動取得」は、まずAndroid対応(ADB)から実装し、iPhone対応(libimobiledevice)は
   その後で良い。手入力へのフォールバックを必ず組み込むこと。
3. 「3. にこスマの価格情報取得バッチ」を実装する。サイトへの配慮（アクセス間隔・robots.txt確認）
   を必ず組み込むこと。
4. 各項目の実装が終わるごとに `npm run lint` と `npm run test` を通してからコミットする。
